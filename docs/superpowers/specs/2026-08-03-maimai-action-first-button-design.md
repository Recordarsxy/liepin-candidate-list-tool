# 脉脉“沟通按钮优先”采集设计

## 目标

脉脉列表页只要出现可见且文字完整为“立即沟通”或“沟通”的控件，就在其左侧显示“加入批量”。按钮显示不得依赖年龄、期望、学历、地点或时间线是否能被解析。

## 设计

- 扫描器以可见沟通文字为唯一按钮锚点，不限制锚点必须是 `button`、`div` 或带 ARIA role 的元素；每个锚点各自挂载一个按钮，共享父容器时也不合并。
- 点击按钮时，从动作锚点向上查找包含可靠姓名的完整候选人行：优先选择同时包含工作/教育时间线的祖先，否则选择候选信息证据最完整的祖先；到达包含多个沟通动作的共享容器或 `body/html` 时停止，禁止借用另一行姓名。
- 姓名解析排除“沟通/立即沟通”等动作文字；找到姓名后，其余 11 列按现有规则尽力解析，无法确认的字段写空字符串。
- 保留批量选择、11 列 TSV、复制成功后自动清空、总开关及猎聘逻辑。
- 仍忽略隐藏文字；完整动作文字之外的普通页面文字不生成按钮。

## 验收

- 没有年龄、期望、学历和时间线的匿名脉脉行，只要有姓名与“立即沟通”，仍显示一个“加入批量”按钮。
- `span`、`p` 等普通元素中的完整沟通文字也能生成按钮；同一父容器的两个沟通锚点各生成一个按钮。
- 点击该按钮不会显示“暂时无法识别”；姓名被加入，其他缺失列为空。
- 当姓名与年龄、地点、期望和经历分属不同子容器时，点击后仍从整行读取这些字段，而不是只复制姓名。
- 原有脉脉与猎聘测试、类型检查和生产构建全部通过。
