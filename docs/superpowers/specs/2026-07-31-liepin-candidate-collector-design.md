# 猎聘金融销售候选人采集器：产品与技术设计

**日期：** 2026-07-31
**状态：** 已批准，等待在生活电脑实施
**目标用户：** 单人猎头研究员
**业务期限：** 20 天内完成约 300 家公司的检索与整理

## 1. 目标与边界

本工具用于建立可复用的金融领域渠道、机构和同业销售人才库。它减少逐卡复制、详情页重复打开、去重和钉钉录入的机械劳动，但把公司搜索、翻页、异常处置和最终质量判断保留给用户。

v1 仅适配猎聘。脉脉未来作为独立页面适配器接入同一套本地数据与复核流程。领英不接入自动化采集；如未来使用，只允许人工处理或平台官方授权能力。

本工具不是无人值守爬虫：它不在后台自行遍历猎聘，不模拟虚拟鼠标，不读取 Cookie，不调用猎聘私有接口，不拦截网络请求，不绕过验证码、登录、频率或访问限制。

## 2. 用户工作流

每家公司按以下步骤处理：

1. 用户从钉钉公司清单选择一家企业，在猎聘手动设置当前公司。
2. 用户分别搜索 `渠道`、`机构`、`同业`，并自行翻页。
3. 扩展检查页面是否存在可能漏人的过滤条件；如存在，显示警告，用户确认后仍可继续。
4. 用户点击“采集本页”。扩展读取当前页最多 30 张候选人卡片。
5. 本地助手标准化字段、校验当前公司、执行岗位纳入/排除规则并去重。
6. 仅匹配者进入当前页详情队列。用户点击“补全本页详情”后，扩展复用一个专用详情标签页串行打开候选人详情。
7. 详情页补充性别和教育经历。遇到登录失效、验证码、访问限制或 DOM 不匹配时立刻暂停，并说明原因。
8. 用户在侧边栏完成该公司的候选人复核，必要时修正或排除。
9. 用户点击“同步本公司”。优先直接写入钉钉；API 不可用时生成九列 TSV 并一键复制，用户粘贴后确认完成。
10. 本地记录公司进度，用户继续下一家公司。

## 3. 数据范围

### 3.1 钉钉主表固定九列

| 顺序 | 列名 | 取值规则 |
|---:|---|---|
| 1 | 目前公司 | 当前最新在职经历中的公司，使用页面可见文本 |
| 2 | 姓名 | 平台脱敏姓氏加详情性别称谓，例如“王先生”“李女士” |
| 3 | 性别 | 详情页明确显示的“男”或“女”；无法确认则留空 |
| 4 | 年龄 | 页面明确显示的年龄；不存在则留空 |
| 5 | 目前地点 | 页面当前地点原文，不自行推断或拆分 |
| 6 | 期望地点 | 只保留页面列出的第一个期望地点 |
| 7 | 目前岗位 | 当前最新在职经历中的职位原文 |
| 8 | 硕士学校 | 教育经历中时间最近的一段硕士学校；没有则留空 |
| 9 | 本科学校 | 教育经历中时间最近的一段本科学校；没有则留空 |

不设置联系方式列，也不采集手机号、邮箱、微信或其他联系信息。若详情页没有性别，保留平台原始脱敏姓名、性别留空，并标记必须人工复核，不能猜测称谓。

### 3.2 岗位纳入词

只根据当前最新在职岗位判断，标准化空格和大小写后匹配以下业务含义：

`渠道销售、渠道业务、渠道经理、渠道总监、渠道负责人、渠道拓展、银行渠道、券商渠道、财富渠道、机构销售、机构业务、机构客户、机构客户经理、机构业务经理、机构业务总监、机构业务负责人、同业销售、同业业务、同业客户`

### 3.3 岗位排除词

`运营、支持、助理、实习、客服、服务、研究、产品、交易、风控、合规、行政`

排除规则优先于纳入规则。例如“机构客户服务”虽然包含“机构客户”，仍然排除。未命中纳入词的候选人不进入详情队列；命中排除词的候选人也不进入。

### 3.4 当前公司判断

每家公司在本地维护：

- 规范公司名；
- 用户确认的别名；
- 可接受的明确分支机构名。

候选人卡片的最新在职经历必须命中以上任一名称。只在历史经历中出现目标公司、公司名模糊或无法确认当前在职状态时，不自动收录，进入人工检查或排除。

## 4. 系统架构

### 4.1 Chrome MV3 扩展

职责：

- 在用户已登录的猎聘标签页中读取当前可见 DOM；
- 解析列表卡片与详情页；
- 提供侧边栏，显示公司、搜索轮次、页码、匹配数、详情进度、异常和复核状态；
- 把结构化数据发送给仅监听本机的后台助手；
- 复用一个专用详情标签页完成当前页最多 30 名匹配者的串行补全；
- 监听页面状态，遇到阻断条件立即暂停。

扩展不得访问或导出 Chrome Cookie，不注入用于隐藏自动化的脚本，不读取网络层私有响应。权限遵循最小化原则，只申请猎聘所需域名、本机助手地址、标签页和侧边栏相关权限。

### 4.2 本地后台助手

技术基线：Python 3.11+、FastAPI、Pydantic、SQLite、pytest，最终用 PyInstaller 打包为 Windows 本地应用。

职责：

- 监听 `127.0.0.1`，拒绝外网网卡访问；
- 与扩展通过首次配对令牌鉴权；
- 存储公司、搜索轮次、候选人、来源、详情、复核和同步状态；
- 执行标准化、岗位过滤、公司匹配、去重和钉钉字段映射；
- 调用钉钉官方开放能力，或生成 TSV 兜底；
- 保存可续跑断点，但不把运行数据上传 GitHub。

### 4.3 钉钉集成

首次运行由用户选择：

- 公司清单所在工作表及公司名列；
- 候选人九列主表；
- 独立的 `系统索引` 工作表。

主表保持固定九列，不增加技术字段。`系统索引` 保存候选人键、九列标准化指纹、同步状态和钉钉行号，用于幂等和故障恢复。公司进度、被排除记录和详细来源只保存在本地。

钉钉权限必须先以临时企业内部应用做最小读写探针。AppSecret 使用 Windows DPAPI 加密后保存，源码和日志中均不得出现明文。若普通钉钉表格没有可用的官方追加接口或企业权限无法取得，则 v1 自动切换为 TSV：按九列顺序复制，用户粘贴并点击“已粘贴”，本地再标记完成。

## 5. 数据模型与去重

建议的核心实体：

- `Company`：规范名、别名、分支名、当前进度和完成状态；
- `SearchRun`：公司、关键词、页码、采集时间、页面警告；
- `Candidate`：稳定猎聘候选人键、九列字段、复核状态、更新时间；
- `CandidateSource`：候选人键、搜索轮次、来源页面、卡片原文摘要；
- `DetailJob`：候选人键、队列顺序、尝试状态、暂停原因；
- `SyncRecord`：候选人键、九列指纹、同步状态、目标行号和错误摘要。

首选去重键是候选人卡片 DOM 中稳定的猎聘候选人标识。重复命中时只保留一条 `Candidate`，但追加 `CandidateSource`，以便知道它在哪个公司关键词和页码出现。若稳定标识暂时缺失，不应仅凭姓名强行合并；使用规范化的公司、岗位、脱敏姓名和教育摘要生成临时候选指纹，并强制人工复核。

九列同步指纹由九个标准化字段按固定顺序计算。同步状态机为：

`pending -> append -> committed`

写入前先在 `系统索引` 查候选人键和指纹。若上次停在 `pending`，重试时先通过指纹核对主表是否已经存在，再决定补记索引或追加，防止断电或超时导致重复行。

## 6. 本机 API 契约

本地助手至少提供以下版本化端点：

- `POST /v1/capture/page`：接收公司上下文、搜索轮次和当前页卡片；返回纳入、排除、待复核与详情队列统计。
- `POST /v1/capture/detail`：接收候选人详情解析结果和页面状态；更新性别、教育及详情作业状态。
- `GET /v1/queue/current-page`：返回当前页按顺序待补全的候选人，最多 30 人。
- `GET /v1/review/{company_id}`：返回该公司的候选人、来源、规则命中原因和缺失字段。
- `POST /v1/sync/{company_id}`：仅同步已复核候选人；优先钉钉，失败时给出可执行的 TSV 兜底状态。
- `GET /v1/export/{company_id}`：生成严格九列顺序的 TSV 文本，不包含技术字段。

接口必须通过 JSON Schema 或 Pydantic 模型固定字段和枚举。扩展和助手共同使用 `contracts/` 中的版本化匿名夹具，防止双方字段漂移。

## 7. 异常与暂停策略

以下任一状态必须暂停连续详情补全：

- 登录已过期或被重定向至登录页；
- 出现验证码、人机验证或访问频率提示；
- 页面显示权限不足、资源消耗确认或异常访问；
- 列表或详情关键 DOM 无法识别；
- 当前专用标签页被用户关闭或导航到非预期页面；
- 本地助手不可达或配对令牌失效。

暂停后保留队列位置，不自动重试循环。用户处理页面并显式点击“继续”后，才从断点恢复。任何验证码和平台限制都不得被规避。

## 8. 安全、隐私与日志

- SQLite 数据库放在当前 Windows 用户的 LocalAppData 专用目录，并设置仅当前用户可访问的 ACL。
- AppSecret 和令牌使用 Windows DPAPI；显示界面只展示末尾少量字符用于辨认。
- 日志只记录时间、阶段、数量、错误类别和匿名记录键；不记录候选人字段全文、Cookie、请求头、令牌或密钥。
- `.gitignore` 排除数据库、CSV/TSV/XLSX、日志、环境变量、密钥、构建产物和本地状态。
- 测试夹具必须人工匿名化，不得从真实候选人页面原样提交。
- 项目结束时提供清理向导，删除钉钉应用、Chrome 扩展、后台应用、凭证、数据库、日志和临时导出。

## 9. 性能与质量目标

- 单次“采集本页”解析 30 张卡片时，正常电脑上目标为 2 秒内给出规则结果；网络不参与列表解析。
- 详情补全是串行、可暂停、可续跑的，绝不以绕过平台限制换取速度。
- 同一稳定候选人键在本地只存在一条主记录；重复来源可追溯。
- 未经人工复核的候选人无法调用同步。
- 钉钉重试不得产生重复行；TSV 始终为九列且顺序固定。
- 对所有纳入词、排除词优先级、公司别名、教育选择、姓名称谓和同步状态机建立自动化测试。

## 10. 完成定义

v1 只有同时满足以下条件才算完成：

1. 用户能完成一家公司的三轮搜索、列表采集、匹配详情补全、人工复核和钉钉同步或 TSV 粘贴。
2. 登录失效、验证码、访问限制和 DOM 变化会安全暂停并可续跑。
3. 九列字段与已确认钉钉表头完全一致，联系方式从全链路缺席。
4. 去重和中断恢复测试通过，不会因重试制造重复钉钉行。
5. 真实密钥、Cookie、候选人数据和日志均未进入 Git。
6. Windows 打包、安装、卸载和项目结束清理流程经过一次实机验证。
