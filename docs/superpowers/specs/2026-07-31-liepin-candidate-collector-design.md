# 共享金融销售人才库：产品与技术设计

**日期：** 2026-08-03
**状态：** 已批准，可据此实施
**目标用户：** 在 Windows + Chrome 上操作的单人招聘研究人员

## 1. 目标、范围与禁止项

V1 建立一个可复用的候选人共享人才库，支持并行的两条工作流：

1. **人才 List 收集**：收集符合宽口径金融销售人才池的候选人，补全九列数据并供人工导出。
2. **岗位专属推荐**：根据用户粘贴的岗位聊天文本创建、审批、版本化并启用岗位规则；对已收集候选人给出推荐结论和证据。

V1 平台为猎聘和脉脉。LinkedIn 明确不进入 V1，因为 LinkedIn 官方规则禁止自动化 LinkedIn 扩展。不得通过另一种自动化途径规避该排除项。

本工具不是爬虫。用户必须手动完成搜索、翻页、站内导航和登录。系统只在用户显式点击采集后读取当时页面的可见 DOM；禁止自动搜索、自动分页、后台轮询平台、私有接口、请求拦截、读取或导出 Cookie、验证码绕过、点击联系方式、保存平台收藏或触发任何联系动作。

## 2. 用户工作流

### 2.1 岗位规则工作流

1. 用户把一段岗位需求聊天文本粘贴进本地助手。
2. 规则解析器抽取职责、目标机构/渠道、职级、地点、必需/排除条件和偏好，生成**草案**，不会自动生效。
3. 用户查看草案的结构化字段、歧义和解析证据，编辑或确认。
4. 用户批准后系统创建不可变版本并将该版本设为 active；新版本取代该岗位旧的 active 版本，但保留历史版本及批准时间。
5. 只有 active 版本参与扫描、重算和推荐。用户可停用岗位而不删除历史结论。

### 2.2 每页收集和匹配工作流

1. 用户在猎聘或脉脉页面手动定位到结果页或详情页，确认页面内容后点击“扫描当前页”。
2. 适配器读取可见 DOM、校验页面状态、抽取允许的结构化职业字段与来源平台 ID。脉脉可见 DOM 不符合预期时，提示用户手动复制**当前页面**文本作为回退输入。
3. 对每个候选人执行宽口径人才池硬规则。符合“金融渠道、机构或同业销售”规则的每位候选人都写入共享库并进入详情队列；不以是否匹配某个岗位作为入队条件。
4. 系统用同一候选人的结构化证据评估每个 active 岗位，向用户展示排名最高且非 `reject` 的 1–3 个岗位及各自结论、证据和反证。
5. 有一个或多个 `recommend` 岗位的候选人先进入深度岗位分析队列。其余入池候选人仍进入九列补全队列，不能被跳过。
6. 用户审核可编辑的九列值和岗位结论，选择要导出的合格候选人。导出只将无表头 TSV 数据行写入剪贴板，用户自行粘贴到钉钉。

### 2.3 脉脉文本回退规则

回退模式只能解析用户从当前可见页面主动复制的文本。解析器不得根据上下文补全、猜测或派生缺失字段；任何无法可靠提取的列必须为 `""`，并创建字段缺失标记和 `needs_review` 证据。文本回退仍服从用户触发、无自动导航和无联系方式采集等边界。

## 3. 判定、证据和九列输出

### 3.1 唯一结论词汇

人才池准入、岗位匹配和人工复核状态只可用以下值：

- `recommend`：硬条件满足，且结构化证据足以支持结论。
- `reject`：存在明确不满足条件的反证，或不符合人才池硬规则。
- `needs_review`：证据不完整、互相矛盾、规则存在歧义或语义分析不可用。

不得使用 A/B/C/D 或任何同义等级。每项结论必须保存 1–3 条简短证据；`reject` 至少保存一条明确反证。证据记录是字段级或经历级摘要，不保存完整简历页文本。

### 3.2 宽口径人才池

候选人最新、可见的职业经历须显示金融领域的渠道销售、机构销售或同业销售信号，且无明确排除信号，才为 `recommend` 并进入详情队列。对最新任职、公司归属或职位语义无法可靠判断时，保留候选人并标记 `needs_review`，由人工决定；不得因未命中某个具体岗位而拒绝入池。

规则实现须将包含词、排除词和机构别名配置为可审计的版本化规则。排除证据优先于模糊的包含词；硬规则只能从结构化、可见字段得出，不依赖模型猜测。

### 3.3 钉钉主表与 TSV

主表严格只有以下九列，顺序不可变：

`目前公司～姓名／性别～年龄／目前地点～期望地点／目前岗位～硕士学校／本科学校`

每条导出记录映射为九个制表符分隔字段、行间以换行分隔；复制内容不含表头、候选人键、岗位名、证据、状态或其他技术列。V1 不调用钉钉 API、不创建或维护钉钉系统索引，也不通过网络写入任何钉钉工作表。

字段只取页面直接可见或经过批准的结构化职业证据。性别、年龄、地点、期望地点、学历或学校无法可靠确定时留空并保留复核标记；不得由姓名、代词、历史信息或模型臆测。

## 4. 共享数据模型和队列

本地 SQLite 数据库按当前 Windows 用户的应用数据目录保存，访问控制仅允许该用户。数据库保存以下实体：

- `candidate`：平台、平台候选人 ID、标准化九列字段、最新职业经历摘要、入池结论和更新时间。
- `career_evidence`：公司、职位、时间范围、地点、教育层次、学校和来源字段；只保存结构化、最小必要的证据，不保存 HTML、完整页面文本或原始简历全文。
- `candidate_source`：平台、用户触发的扫描时间、页面类型、可审计的最小来源描述和字段缺失标记。
- `job` 与 `job_rule_version`：用户输入文本的最小摘要、草案/批准/停用状态、版本号、规则、批准人（本地用户）和时间。
- `job_assessment`：候选人、active 规则版本、`recommend`/`reject`/`needs_review`、排序分数、1–3 条证据或反证、模型/规则来源和时间。
- `detail_queue`：候选人、队列种类（`recommended_deep_analysis` 或 `nine_column_enrichment`）、优先级、状态和暂停原因。

以 `(platform, platform_candidate_id)` 去重。没有可靠平台 ID 时创建临时记录、不得把相似姓名自动合并，并强制 `needs_review`。每次采集都会重新评估所有 active 岗位；界面只展示排名前 1–3 个可行动结果，但数据库保留各岗位本次结论以便审计。

队列优先级为：存在 `recommend` 岗位的候选人先做深度岗位分析；然后处理所有仍未完成的九列补全任务。一个候选人可同时在两个队列拥有不同工作项，完成深度分析不取消其九列补全义务。

## 5. 平台适配器和界面

Chrome MV3 扩展提供当前页扫描、当前页详情补全、岗位草案审核、候选人复核和 TSV 复制界面。它仅连接本机 `127.0.0.1` 助手，并采用一次性用户配对令牌。扩展权限须最小化，清单中不得含 cookie、webRequest 或覆盖平台行为的权限。

猎聘适配器解析用户已打开页面的可见 DOM；检测登录失效、验证码、访问受限或 DOM 不匹配时暂停并报告原因，不自动重试或导航。

脉脉适配器先从用户触发时的可见 DOM 解析。若选择器不匹配或字段无法稳定定位，界面显示“粘贴当前页文本”回退区。回退结果须注明 `manual_text_fallback`、逐字段缺失标记和可复核的原始输入哈希（不能存储原文）。

## 6. AI、隐私和故障降级

复杂岗位语义匹配使用 OpenAI Responses API，默认模型为 `gpt-5.6-terra`、reasoning effort 为 `medium`，并要求结构化输出。请求构造器必须在发送前移除候选人姓名、平台 ID、联系方式和 URL；任何联系字段一经出现即拒绝发送。只发送实现匹配所需的去标识化结构化职业证据。

API key 仅用 Windows DPAPI 加密存储。日志只能记录匿名事件 ID、计数、处理阶段和错误类别，禁止候选人文本、姓名、简历、凭证、Cookie、API 请求体、响应体或秘密。测试需验证这些禁项。

Responses API 超时、认证失败、格式错误或不可用时：本地字段提取、去重、宽口径硬规则、队列和 TSV 映射照常运行；只有需要复杂语义的岗位结论改为 `needs_review` 并附带“AI analysis unavailable”的证据。不得将失败误报为 `reject` 或自动重试平台页面。

## 7. 验收标准

- 用户能在两平台手动定位页面并显式触发扫描；系统不进行自动搜索或自动分页。
- 每名通过宽口径人才池规则的候选人都进入详情队列；推荐候选人先做深度分析，其余候选人仍获得九列补全。
- 用户批准、版本化的岗位规则会在每次扫描时对所有 active 岗位执行评估，界面展示前 1–3 个匹配岗位。
- 所有结论及证据只用 `recommend`、`reject`、`needs_review`，不出现 A/B/C/D。
- 脉脉可见 DOM 与手动文本回退均可运行；回退的缺失字段空白且标记，不会推断。
- 剪贴板只含无表头九列 TSV 数据行，且没有钉钉 API 调用。
- 安全扫描、日志测试和实际页面验收均未发现候选人文本、Cookie、密钥、请求体或违规自动化行为。
