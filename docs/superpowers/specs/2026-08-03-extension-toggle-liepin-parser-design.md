# 扩展总开关与猎聘卡片解析修复设计

## 背景与目标

当前猎聘真实缩略卡片使用 `new-resume-personal-*` 等稳定语义类名，并把工作、教育经历放在结构化经历行中。现有解析器主要面向匿名夹具里的通用 `data-field` 和 `candidate-name` 等选择器，因此无法取得姓名以及目前公司或岗位，点击后会显示“暂时无法识别”。

本次变更实现两个目标：

1. 修复猎聘真实缩略卡片的字段识别，同时继续遵守只读取当前可见内容、缺失留空、不推断的约束。
2. 在侧边栏顶部增加一个持久化总开关，一键关闭或重新开启猎聘、脉脉页面上的采集按钮。

## 方案选择

采用“稳定字段选择器 + 经历结构识别”。不依赖猎聘构建生成的随机 CSS 类名，也不对整张卡片做无边界文本猜测。

- 姓名、年龄、目前地点使用猎聘稳定语义类名。
- 期望地点、期望岗位使用求职期望区域中可见字段的既定顺序。
- 目前公司和目前岗位取第一条明确的工作经历行，并按页面展示的分隔符拆分。
- 硕士、本科学校仅从明确包含“硕士”或“本科”层级的教育经历行提取。
- 本科入学时间取对应本科经历时间段的四位开始年份。
- 性别只接受页面明确显示的“男”或“女”；不得从“先生/女士”推断。
- 任一字段无法可靠确认时返回空字符串。

解析器保留现有通用选择器作为匿名夹具和兼容路径，猎聘专用结构解析作为该站适配器的补充。

## 总开关设计

侧边栏顶部显示一个状态明确的按钮：

- 开启时显示“采集已开启”，点击后切换为关闭。
- 关闭时显示“采集已关闭”，点击后切换为开启。
- 默认值为开启，状态保存在 `chrome.storage.local` 的 `collectorEnabled`。

猎聘和脉脉内容脚本启动时读取该状态，并监听 `chrome.storage.onChanged`：

- 关闭后停止 `MutationObserver`，移除所有由扩展插入的“加入待办”按钮。
- 开启后重新扫描现有卡片、恢复 `MutationObserver`，动态加载的新卡片继续获得按钮。
- 切换不删除待办池数据，不影响本地助手或钉钉配置。

侧边栏负责写入开关状态，不需要枚举标签页或申请额外权限。存储变更事件会自动传播给已打开的猎聘和脉脉页面。

## 数据流与错误处理

1. 内容脚本确认采集处于开启状态并为候选卡片插入按钮。
2. 用户点击按钮后，猎聘适配器从当前卡片的可见 DOM 生成固定字段草稿。
3. 姓名缺失，或公司与岗位同时缺失时，仍拒绝生成空候选人并显示“暂时无法识别”。
4. 解析成功后沿用现有本地助手捕获、去重和待办流程。
5. 本地助手不可用时按钮显示“重试”，不会伪装成已加入。

开关状态读取失败时采用安全默认值“开启”，保持与当前版本一致；写入失败时侧边栏显示错误，不提前改变按钮文案。

## 测试策略

测试按红—绿流程补充：

- 使用从真实页面结构抽象、完全匿名化的猎聘夹具，先复现“暂时无法识别”。
- 验证姓名、年龄、地点、期望地点、期望岗位、目前公司、目前岗位、硕士学校、本科学校及本科入学年份。
- 验证不从脱敏称谓推断性别，缺失字段保持空字符串。
- 验证关闭开关会移除按钮并停止动态注入，重新开启会恢复且不会重复插入。
- 验证侧边栏正确读取、展示和持久化开关状态。
- 运行扩展全量单元测试、类型检查和生产构建。

## 发布与验收

构建通过后，将新的 `manifest.json`、`sidepanel.html` 和 `dist` 覆盖到桌面安装目录。用户在扩展管理页点击一次“重新加载”，无需重新配对。最终在当前猎聘缩略页验证：按钮可开关；点击一张匿名测试卡片后进入待办而不再显示“暂时无法识别”。脉脉只验证开关行为，原字段解析行为不得回退。
